# 受託学習データの受付と事前検査

## 受領から検収まで

1. データを受け取る前に、利用権限、個人情報、秘密保持、保管場所・期限、受渡し方法を合意する。最初の問い合わせでは対象クラス、撮影条件、端末、納期、画像枚数の見込みを聞く。
2. 顧客とクラス定義、対象外と意図的な負例、シーン・撮影時刻・カメラ・連続フレームをまたぐ分割、検収用データを決める。ツールには確定した train と val を指定する。運用上の最終検収セットは学習・モデル選定と分離して管理する。
3. 受領済みの作業コピーをオフラインで検査する。内容が修正された場合はデータの版、分割、指摘と回答を記録して再検査する。
4. 目視でラベル粒度・漏れ・枠精度を確認し、顧客と検収基準と評価環境を決める。合意に応じて重み、推論例、評価報告、第三者条件を納品し、素材と中間物を合意した範囲・期限に従い消去する。[契約とデータ運用](rights-review.md)

## 手元で検査する

[受付ツール](../materials/intake_dataset.py)は Python 3.12 と Pillow を使用。専用環境に依存を用意した後に実行する。ファイルの読み込み、検査、JSON書き出しまでをローカルで行う。報告書には相対ファイル名や不正入力の記述が入る場合があるため、顧客データと同じ承認済み領域で取り扱う。

### YOLO 検出 TXT

`classes.txt` は UTF-8 の1行1クラス名。先頭行がクラスID 0。画像とラベルは、各ルートで相対パスの拡張子を除いた部分を揃える。例えば `images/train/camera1/0001.jpg` と `labels/train/camera1/0001.txt` を対応させる。各行の形式は `class_id cx cy w h` で、座標は画像幅・高さに対する正規化値。意図的な負例は空のTXTを置く。セグメンテーションや回転枠には専用の受領仕様が必要。

```powershell
python intake_dataset.py yolo --classes classes.txt --train-images images/train --train-labels labels/train --val-images images/val --val-labels labels/val --report intake-yolo.json --output-dir converted-coco
```

`--output-dir` は変換する場合に指定し、存在しないディレクトリ名を使う。検査が通ると、`instances_train.json` と `instances_val.json` が出力される。画像は元のルートにあり、変換JSONからのファイル名は各画像ルートに相対。カテゴリIDは元のクラスID＋1、画像IDは各分割内で相対パス順に1から、アノテーションIDは画像順とTXTの行順に1から付与。元画像・元ラベルは読み取り専用で扱い、画像に EXIF 回転がありラベル作成時に適用した場合は受領前に画像と座標系を揃える。

### COCO bbox JSON

```powershell
python intake_dataset.py coco --train-images images/train --train-json annotations/instances_train.json --val-images images/val --val-json annotations/instances_val.json --report intake-coco.json
```

各COCO JSONは `images`、`annotations`、`categories` を持ち、両分割でカテゴリIDと名前の対応が一致するようにする。bboxはピクセル単位の `[左, 上, 幅, 高さ]`。bbox検査は画像ファイルのデコード寸法、参照ID、範囲・正の面積、重複行を確認。報告対象はJSONに登録された画像。分割をまたぐ重複は同じ物理パスまたはファイルバイトの SHA-256 一致で検出する。トリミング、再エンコード、近接フレームなどの類似画像は別途確認する。COCOのポリゴンやマスク、各形式のラベルの意味と網羅性は目視確認の対象。

終了コード0は検査通過、1は報告書に指摘あり、2は入力ファイルや出力先などの実行エラー。報告書名は毎回新しくし、出力先の親フォルダーを先に用意する。入力数・カテゴリ別ラベル数は受付確認に使える。報告書の件数は入力と指摘の把握用で、合格・精度の保証には使わない。

## 見積もりの根拠と確認項目

| 記録済みの実績 | 条件 |
| --- | --- |
| 学習ループ計 162,554.80 秒（約45.15時間） | COCO 2017 の学習用116,287枚、選定用2,000枚、640 × 640、GeForce RTX 5090、300エポック、BF16、物理バッチ32、目標実効バッチ64 |
| 1エポック中央値 542.84 秒（約9.05分） | 同じ実行の `train_seconds` |
| GPU由来の最大ピーク割当 16.906 GiB、最大ピーク予約 18.459 GiB | 同じ実行の PyTorch メモリ記録 |

学習ループ時間の合計を、案件全体の待ち時間や作業時間と分けて扱う。顧客データの規模、入力サイズ、モデル、評価頻度、学習設定、GPUを確定し、許可された案件で短い予備実測を取って所要時間と必要メモリを見積もる。追加でラベル修正、データ受け渡し、評価・再学習、受け入れ検証の工数を積み上げる。実作業工数、価格、納期の検証済み標準値は現時点で未設定。
